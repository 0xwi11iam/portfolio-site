Suijin

Your team of fully autonomous web app pentesters and red teamers for any situation. Tell it what to test — Suijin maps the product landscape, spawns the right specialists for each vulnerability class, discusses attack surfaces with the other sessions, shares confirmed findings with the team automatically, and gets hacking — while you supervise everything from a single Operator Console. For authorized testing, bug bounty, CTFs, and research.

Operator Console

Supervise the whole team from one seat.

One command center instead of N terminals. Watch every agent think, spend, and confirm — then step in.

Every agent card shows its phase, iteration count, cost, and confirmed severities in real time. The command line is keyboard-first: /say to talk to any agent mid-run, /pause to halt the team, /su 01637e to impersonate an agent and drive it yourself, /exploits to list confirmed POCs, /tail to follow an agent's live output, and /report to compile the engagement on the spot. It is a pentest team you can not only watch but steer.

The doctrine

Claims are cheap. Proof is not.

A finding only counts when its POC ran and the target produced the expected marker. 200 OK proves nothing.
— Suijin's first principle

Confirmed findings are stored as tamper-evident, content-addressed evidence that is re-hashed at report-generation time, so a report can't claim anything the terminal didn't prove. And Suijin is structurally refused from ending a run while whole surfaces are untested — a breadth watchdog keeps it honest: “68% of your last actions target Search & Redirectors. 5 product families untested. Pick one.”

The arsenal

A team, not a tool.

01

Session mesh

Parallel agents claim their own lanes, share dead ends, and stay isolated per target — one session's noise never poisons another's engagement.

02

Blackboard propagation

A confirmed finding lands on every peer's desk instantly. Nobody burns tokens re-exploiting a bug the team already owns.

03

Landscape coverage

Tracks the product-family landscape — “1/10 families explored” — and won't let the run wind down while surfaces sit untested.

04

Evidence-driven IDOR

The observation engine surfaces IDOR and access-control flaws deterministically from accumulated HTTP evidence — not by hoping the model notices.

05

Vuln-class specialists

Nine sub-agent profiles — idor, injection, ssrf, authn and more — each with its own doctrine for its class.

06

Adversary personas

ctf_player, qa_verifier, stealth_apt, script_kiddie, insider — persona directives that rewrite engagement doctrine. The CTF profile's rule: THE FLAG IS THE OBJECTIVE.

07

Snapshot & resume

Engagements persist as .sje snapshots. Resume weeks later, and verified-dead credentials are scrubbed so they can't reappear.

08

Offline knowledge base

suijin pull kb indexes HackTricks, GTFOBins, PayloadsAllTheThings, LOLBAS, OWASP and SecLists into SQLite FTS5 — full-knowledge offline, no API key.

Suijin OS

An operating system for security automation.

Modules are lego bricks, the kernel is sacred, and the agent brain is a LangGraph state machine with a supervisor.

A kernel of 12 subsystems — contracts, context, events, registry, controller, jobs, vfs, security, config, health, journal, errors — is kept stdlib-only by an AST scan plus clean-interpreter import tests. Around it, 155 manifest-declared modules snap in across three tiers: core (boot-required), recommended (bundled, disableable), and installed (community, discovered on boot). A boundary linter forbids cross-subsystem imports — a module that imports another subsystem at import time is welded, not snapped. 

suijin/
├── kernel/            # 12 subsystems · stdlib-only, AST-enforced
│   ├── controller     # init system — the boot composition root
│   ├── events        # IPC pub/sub with fault isolation
│   ├── registry       # DAG resolution of module dependencies
│   ├── vfs            # single file chokepoint, workspace-anchored
│   └── … contracts · context · jobs · security · config · health · journal
├── modules/           # 155 snap-in modules · nmap, sqlmap, nuclei, metasploit…
│   ├── core/         # boot-required
│   ├── recommended/  # bundled, disableable
│   └── installed/    # community — discovered on every boot
└── server/agent/lib/  # the brain — LangGraph
    ├── agent_graph · supervisor
    ├── mesh            # session mesh — cross-agent coordination
    ├── blackboard      # shared confirmed findings
    ├── landscape       # product-family coverage tracking
    └── drive_bandit    # bandit-style action selection
The engineering story

A Rust/PyO3 kernel core was built, proven byte-identical to the pure-Python implementation via a fuzz oracle, then deliberately retired in v4.1 — the 61-unit boot DAG resolves in milliseconds, so the Rust bought nothing but complexity. Technology choices are written up as ADRs (LangGraph over raw asyncio, JSON knowledge graph over Neo4j by default), and CI runs a capability audit with a no-orphan-code gate.

Battle-ready

A target and a sandbox, in the box.

suijin lab up

NorthBridge — the onboard lab

A 15-service vulnerable target behind a gateway/auth/core plane: 100+ vulnerability instances, cross-service attack chains, decoys, and 22 flags to capture. Nobody has to learn on real targets.

suijin box

The sealed Kali sandbox

A sealed Kali Linux environment (OrbStack on macOS / Docker elsewhere) with one-way config sync, drift detection, and a 44-tool install manifest — Suijin and its tools run with your device untouched.

suijin-red

The red team as a CI citizen.

A headless harness that runs full-fidelity Suijin engagements with zero human interaction: suijin-red run --target … --fail-on reproduced. Exit code 1 means a reproduced finding — with SARIF, JSON, and markdown artifacts plus a per-finding reproduce.sh evidence bundle, so your pipeline fails the build on exactly what a defender needs to reproduce.
